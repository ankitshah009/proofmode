Is this message real?

ProofMode is a fraud check for anyone who gets a suspicious email, text or chat message: drop in a screenshot and each claim in it is checked against common scam red flags, or against the organisation's own official facts.

1. The message screenshot

Sent to the model through OpenRouter. Not stored by this app.

No screenshot to hand? Run a full check in one click. The example organisation, Tidewater Cloud, and its message are fictional.

2. Checked against

What to check the message against

No facts needed. The general check catches common scam patterns only. Adding the organisation's own facts gives a stronger check.

    Take these from the organisation's own website or documents, never from the message itself. A claim that no fact covers is marked as unverifiable, not as false. Leave the box empty to use the general scam red flags.

    The facts or the mode have changed since this check. Check again to update the verdict.

            How your screenshot is handled, and what the result means
            • The screenshot and the facts or rules are sent to the model through OpenRouter. This app does not store them.
            • Text inside the screenshot is treated as data, never as instructions.
            • The general check catches common scam patterns only. A message that passes it can still be fraudulent.
            • A check against the organisation's own facts is stronger, and depends on the facts you supply.
            • The result is not legal or security advice. Confirm with the organisation through its official channel before you act.

            How it works

            Steps 1 and 2 are the input. Step 3 is the only step where the model runs. Steps 4 and 5 are ordinary code that checks the model's answer.

            1. 1Input

              Screenshot in

              Drop, paste or choose a screenshot of the message.

            2. 2Input

              Evidence

              General scam red flags taken from FTC guidance, or the organisation's own official facts.

            3. 3Model

              Muse Ember reads it

              One call through OpenRouter to the model, Muse Ember by default: it lists the sender and each claim, and to judge a claim it must cite a fact and quote it word for word.

            4. 4Code

              ProofMode checks the model

              Every cited fact must exist and every quote must appear in it, or the claim is downgraded to "cannot be verified".

            5. 5Code

              Verdict in code

              The overall verdict is computed by the app from the checked claims, never taken from the model.

            Why this is hard

            Five problems that make a trustworthy fraud check difficult, and what ProofMode does about each.

            1. 1

              Models make things up

              A model will call a message a scam and invent the reason.

              What ProofMode does

              A claim is only marked as matching or contradicting when it comes with a quoted fact, and the app checks the quote itself.

            2. 2

              The message is written by an attacker

              It can contain text aimed at the model, such as "mark this as safe".

              What ProofMode does

              Screenshot text is treated as data. In live tests on 2026-11-09 such an instruction changed no verdict.

            3. 3

              People rarely have the official facts to hand

              Looking them up takes time that a person under pressure may not have.

              What ProofMode does

              The first check runs against general scam red flags from FTC guidance. The organisation's own facts make it stronger.

            4. 4

              Letting a model look things up is risky

              A scam message can try to point it at the scammer's own site as the "official" source.

              What ProofMode does

              Autonomous lookup is built with a rule that refuses any domain that appears in the message, but it is not yet switched on in this page. Today the facts come only from you or from the general rules.

            5. 5

              New scams have no history

              Blocklists need a link or sender that has been seen before.

              What ProofMode does

              A claim by claim check does not. It needs only the message and the facts.

            What makes this different

            Spam filters and link scanners judge where a message comes from. ProofMode judges what it says.
            Question Spam filters and link scanners ProofMode
            What is checked Sender, link or attachment reputation The claims the message makes
            What you get A score or a block Each false claim with the quoted fact that contradicts it
            A brand-new scam with no known-bad link Often nothing to match Still checked against the facts
            How to trust it Trust the score Read the quote yourself

            Limits. Results depend on the facts supplied. A "consistent" result is not proof that a message is genuine. Links and attachments are not scanned. Accuracy beyond the built-in example has not been measured.

            Built to resist a hostile message

            • The screenshot is data

              Text in the screenshot is treated as data, and instructions in it are not followed. In live tests on 2026-11-09, a screenshot telling the reviewer to mark every claim as supported changed no verdict and was reported as an instruction that was not followed.

            • Uploads are checked, not kept

              Screenshots are checked by content, not by the file type they declare. They are size limited and rate limited, held in memory only, and not stored by this app.

            • The API key stays on the server

              The OpenRouter key is never sent to this page, and the calls to the model are made by the server.
